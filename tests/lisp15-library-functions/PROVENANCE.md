# Provenance: LISP 1.5 Appendix A library functions (issue #7, Фаза 2)

На відміну від `tests/lisp15-library-primitives/` (реальні asm-
примітиви), функції тут -- звичайний Lisp-код через `LABEL`/`LAMBDA`
у `startup.lisp`, що спирається на примітиви з попередньої частини
(`NULL`, `EQUAL`, `ATOM`, `CONS`, `CAR`, `CDR`). Джерело те саме:
**LISP 1.5 Programmer's Manual (1962), Appendix A** (ст.67-69).

## Реальна знахідка: `SUBST` у `startup.lisp` не відповідав формулі

До цієї сесії `startup.lisp` уже мав рукописний `SUBST`, але:
- перевіряв `(ATOM Z)` **раніше** за рівність із `Y`;
- використовував `EQ` (pointer identity), не `EQUAL` (структурна рівність).

Точна формула з Appendix A, ст.67:

```
subst[x;y;z] = [equal[y;z] -> x; atom[z] -> z;
                T -> cons[subst[x;y;car[z]];subst[x;y;cdr[z]]]]
```

Це не дрібниця: стара версія **не могла** підставити замість цілої
під-структури, що структурно дорівнює `y` (лише замість одиночного
атома). Fixture `02` демонструє це напряму: `(SUBST X (P Q) ((P Q) B
(P Q)))` дає `(X B X)` з фіксом; adversarially підтверджено, що стара
версія на цьому ж вводі давала `((P Q) B (P Q))` -- **жодної
підстановки взагалі**.

## Реальна знахідка: `startup.lisp` вантажиться відносно CWD процесу

Kernel читає `"startup.lisp"` (літеральний відносний шлях, звичайна
Unix `fopen`-семантика) -- **не** відносно розташування самого
бінарника чи репо. Усі `tests/*/run.sh` раніше запускали kernel, поки
CWD була тестова піддиректорія (`cd "$(dirname "$0")"` на початку
кожного скрипта) -- тож `startup.lisp` **мовчки не завантажувався**
у жодному з попередніх тестових прогонів. Це не мало значення для
`#9`/`#27`/hardware-примітивів (жоден їхній fixture не викликає
library-функцію), але для *цього* корпусу дало **тихо неправильні
відповіді** (`NIL` для кожного fixture) замість помилки -- саме
завдяки більш ранньому фіксу issue "unbound function call no longer
crashes" (`plain_call` тепер тихо повертає `NIL` замість краху, що
тут виявилось оберненою стороною тієї ж медалі: тиха помилка замість
явної). Виправлено в усіх `tests/*/run.sh`: kernel тепер завжди
запускається з `$REPO_ROOT` як CWD.

## Fixtures

| Fixture | Функція | M-вираз (Appendix A) |
|---|---|---|
| `01` | `SUBST`, атомарна ціль | `subst[x;y;z]`, ст.67 |
| `02` | `SUBST`, структурна ціль (regression witness) | той самий, демонструє фікс |
| `03`/`04` | `MEMBER` | `member[x;l] = [null[l]→NIL; equal[x;car[l]]→T; T→member[x;cdr[l]]]`, ст.68 |
| `05`/`06` | `APPEND` | `append[x;y] = [null[x]→y; T→cons[car[x];append[cdr[x];y]]]`, ст.68 |
| `07` | `MAPLIST` -- f отримує ЛИШОК списку, не елемент | `maplist[x;f] = [null[x]→NIL; T→cons[f[x];maplist[cdr[x];f]]]`, ст.69 |
| `08` | `MAPLIST`, порожній список | той самий |

## Adversarial verification

`SUBST`'s фікс підтверджено реально: стара (ATOM-first, `EQ`) версія
в НЕ закомічену копію `startup.lisp` дала `((P Q) B (P Q))` замість
`(X B X)` на fixture `02` -- жодної підстановки. Копію видалено,
трекований `startup.lisp` не змінювався під час перевірки.

`MAPLIST`'s відмінність від element-wise map перевірена напряму:
`f=WRAPFIRST` (обгортає `Y` навколо всього переданого списку) дає
`((Y A B C) (Y B C) (Y C))` -- кожен виклик отримує ЛИШОК `(A B C)`,
`(B C)`, `(C)`, не окремі елементи `A`, `B`, `C`.
