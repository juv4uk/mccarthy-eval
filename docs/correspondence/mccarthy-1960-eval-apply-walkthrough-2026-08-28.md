## Нотація спочатку

`f[x;y]` — виклик функції `f` з аргументами `x`, `y` (як `f(x,y)`,
тільки квадратні дужки — тодішня M-notation).
`[p1 → e1; p2 → e2; T → e3]` — це `cond`: перевіряй `p1`, якщо
істина — результат `e1`; інакше перевіряй `p2`; `T` (true) в кінці —
"у всіх інших випадках".
`car[e]`/`cdr[e]` — перший/решта елементів списку `e`. `cadr[e]` =
`car[cdr[e]]` = другий елемент. `caddr[e]` = третій. `caar[e]` =
`car[car[e]]` — перший елемент першого елемента.

## Дійові особи

- `e` — вираз, який треба обчислити (сирий код, S-вираз).
- `a` — оточення (environment): список пар `(символ . значення)`,
  наприклад `((X . A) (Y . B))`.

## `appq` — маленький помічник

```
appq[m] = [null[m] → NIL; T → cons[list[QUOTE; car[m]]; appq[cdr[m]]]]
```

Бере список і "цитує" кожен елемент. `appq[(A B)]` → `((QUOTE A)
(QUOTE B))`. Навіщо: коли `apply` отримує ГОТОВІ значення аргументів
(не код, а вже обчислені дані), а `eval` очікує код — треба обгорнути
кожне значення в `QUOTE`, щоб `eval`, побачивши їх знову, не
намагався їх ще раз обчислювати.

## `apply` — вхідні двері

```
apply[f;args] = eval[cons[f; appq[args]]; NIL]
```

`apply[CONS; (A B)]`: `cons[CONS; appq[(A B)]]` = `cons[CONS; ((QUOTE
A) (QUOTE B))]` = `(CONS (QUOTE A) (QUOTE B))`. Тобто `apply` просто
**збирає виклик функції як код** і віддає його `eval`. Уся реальна
робота — в `eval`.

## `eval` — серце всього

```
eval[e;a] = [
    atom[e]              → assoc[e;a];
    atom[car[e]]         → [
        eq[car[e];QUOTE]  → cadr[e];
        eq[car[e];ATOM]   → atom[eval[cadr[e];a]];
        eq[car[e];EQ]     → [eval[cadr[e];a] = eval[caddr[e];a]];
        eq[car[e];COND]   → evcon[cdr[e];a];
        eq[car[e];CAR]    → car[eval[cadr[e];a]];
        eq[car[e];CDR]    → cdr[eval[cadr[e];a]];
        eq[car[e];CONS]   → cons[eval[cadr[e];a]; eval[caddr[e];a]];
        T                 → eval[cons[assoc[car[e];a]; evlis[cdr[e];a]]; a]
    ];
    eq[caar[e];LABEL]     → eval[cons[caddar[e];cdr[e]]; cons[list[cadar[e];car[e]];a]];
    eq[caar[e];LAMBDA]    → eval[caddar[e]; append[pair[cadar[e];evlis[cdr[e];a]];a]]
]
```

Читаємо гілку за гілкою:

**1. `atom[e] → assoc[e;a]`** — якщо `e` просто символ (не список),
значить це змінна. Знайди її значення в оточенні `a`. `assoc[X;
((X.A)(Y.B))]` = `A`.

**2. `atom[car[e]] → [...]`** — якщо `e` — список, і перший елемент
цього списку сам є атомом (символом, а не вкладеним списком) — це або
вбудована форма (`QUOTE`, `CAR`, `CONS`...), або звичайний виклик
функції на ім'я. Заходимо у внутрішній `cond`:

- `QUOTE` → просто поверни `cadr[e]` як є, без обчислення.
- `ATOM`/`CAR`/`CDR` → обчисли `cadr[e]` (один аргумент), застосуй
  операцію.
- `EQ`/`CONS` → обчисли `cadr[e]` і `caddr[e]` (два аргументи),
  застосуй операцію.
- `COND` → делегуй у `evcon`.
- **`T →` (нічого з вищого не підійшло)** — це звичайний виклик
  функції: `car[e]` — ім'я функції (наприклад `FF`), знайди її
  визначення через `assoc[car[e];a]`, обчисли всі аргументи через
  `evlis`, склади новий вираз `(визначення-функції
  обчислені-аргументи...)` і віддай знову в `eval`.

**3. Дві останні гілки (поза внутрішнім `cond`, коли `car[e]` — НЕ
атом, а сам список)** — це коли функція викликається "на льоту", без
імені: `((LAMBDA (X) ...) A)`.

- `LABEL` — іменована рекурсивна функція: додай пару `(ім'я .
  сама-функція)` в оточення, обчислюй далі.
- `LAMBDA` — анонімна функція: візьми параметри (`cadar[e]`), обчисли
  аргументи (`evlis[cdr[e];a]`), **спарируй їх** (`pair`), **додай
  спереду оточення** (`append`), обчисли тіло (`caddar[e]`) у цьому
  новому, розширеному оточенні.

## `evcon` і `evlis` — прості цикли

```
evcon[c;a] = [eval[caar[c];a] → eval[cadar[c];a]; T → evcon[cdr[c];a]]
evlis[m;a] = [null[m] → NIL; T → cons[eval[car[m];a]; evlis[cdr[m];a]]]
```

`evcon` — перебирає пари `(тест результат)`, обчислює тест, якщо
істина — обчислює й повертає результат, інакше йде до наступної пари.
`evlis` — обчислює кожен елемент списку по черзі, збирає в новий
список значень (це те, що готує аргументи перед викликом функції).

## Трасування №1 — просте: `(CONS (QUOTE A) (QUOTE B))`

```
eval[(CONS (QUOTE A) (QUOTE B)); NIL]
  atom[e]? ні (це список)
  atom[car[e]]? car[e]=CONS — так, атом → внутрішній cond
    eq[car[e];QUOTE]? ні   eq[..;ATOM]? ні   eq[..;EQ]? ні   eq[..;COND]? ні
    eq[..;CAR]? ні   eq[..;CDR]? ні
    eq[car[e];CONS]? ТАК →
      cons[ eval[(QUOTE A);NIL] ; eval[(QUOTE B);NIL] ]

  eval[(QUOTE A);NIL]:
    atom[car[e]]? car[e]=QUOTE — так → eq[..;QUOTE]? так → cadr[e] = A

  eval[(QUOTE B);NIL] аналогічно → B

  Результат: cons[A;B] = (A . B)
```

## Трасування №2 — виклик лямбди: `((LAMBDA (X) (CONS X X)) (QUOTE A))`

```
e = ((LAMBDA (X) (CONS X X)) (QUOTE A)), a = NIL

atom[e]? ні
atom[car[e]]? car[e] = (LAMBDA (X) (CONS X X)) — це список, НЕ атом → пропускаємо внутрішній cond

eq[caar[e];LABEL]? caar[e] = LAMBDA ≠ LABEL → ні
eq[caar[e];LAMBDA]? ТАК →
  eval[ caddar[e] ; append[pair[cadar[e]; evlis[cdr[e];a]]; a] ]

  cadar[e]  = (X)              -- список параметрів
  caddar[e] = (CONS X X)       -- тіло функції
  cdr[e]    = ((QUOTE A))      -- список аргументів (сирих, ще не обчислених)

  evlis[((QUOTE A)); NIL] = (eval[(QUOTE A);NIL]) = (A)   -- обчислили аргументи

  pair[(X); (A)] = ((X . A))                              -- X спарено з A
  append[((X.A)); NIL] = ((X.A))                          -- нове оточення

  eval[(CONS X X); ((X.A))]:
    atom[car[e]]? CONS — атом → eq[..;CONS]? так →
      cons[ eval[X;((X.A))] ; eval[X;((X.A))] ]

      eval[X;((X.A))]: atom[X]? так (X — символ) → assoc[X;((X.A))] = A

    cons[A;A] = (A . A)

Результат: (A . A)
```

## Головний висновок трасування

`a` (оточення) тут — не побічна деталь, а буквально те, що переносить
значення `X` крізь увесь виклик: гілка `LAMBDA` будує НОВЕ оточення
(`append[pair[...];a]`), і саме в ньому обчислюється тіло. Це той
самий механізм, у якому в 1959 знайшли баг зі "змінними, захопленими
лямбдою" (перша знахідка errata AIM-8, див.
`mccarthy-1960-eval-apply-primary-source-2026-08-28.md`) — і той самий
механізм, через який пізніше Джеймс Слейгл зловив баг із `testr`
(McCarthy, "History of Lisp", 1979): рекурсивний виклик додає нову
пару спереду `a`, і якщо це робиться неправильно, зовнішнє `X`
підмінюється внутрішнім — динамічний scoping замість лексичного. Один
і той самий рядок коду (`append[pair[...];a]`) — і джерело потужності
мови, і джерело найвідомішого раннього бага в її історії.

## Зв'язок із my-lisp

`eval` у нашому `crates/my-lisp/src/language_items.rs` — фіксована
syntax form, поруч із `quote`/`cond` (не восьмий примітив), що точно
відповідає структурі, яку ми тут бачимо: `eval` побудований ІЗ семи
примітивів, не є окремим від них шаром. `apply` як окремий іменований
примітив у my-lisp наразі відсутній (source-confirmed, перевірено
`grep` того ж вечора) — механізм виклику функції всередині evaluator-а
є, але явного `(apply f args)` з коду викликати не можна.
